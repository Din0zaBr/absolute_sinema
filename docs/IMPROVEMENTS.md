# Backlog улучшений детекции (борьба с FP, recall, сопоставление)

Составлено 2026-07-07 по итогам ручного разбора ~40 сцен набора и сверки с кодом.
Цель файла — чтобы не пере-выводить этот анализ заново. Факты из кода на момент
написания: `imgsz=1024`, `det_conf=0.25`, `det_iou=0.45`, ансамбль (второй
pothole-проход) ВЫКЛ по умолчанию, `mask_min_area_px=200`, `mask_min_area_linear_px=60`
(с цикла 13 на кадрах < ~2.9 МП пороги масок масштабируются вниз — на кадрах
набора не меняются), детектор — открытые веса RDD2022 (rezzzq), 5 классов,
домен ≠ РФ-дворы.

## Наблюдённая карта ложных срабатываний (реальные примеры из набора)
1. **На припаркованных машинах**: колёса, фары, номера (сцены 029, 032, 016).
   Дворы забиты машинами — источник FP №1.
2. **Не на дороге / вертикальные объекты**: кирпичная и розовая стены, билборды,
   **детские рисунки/плакаты** (цветок → ложный «люк 646мм» → фейковые «~43.8см» на
   047; «English»-баннер), земляные клумбы (003, 009, 038, 044, 047).
3. **Заделанные заплатки** (светлые, гладкие, вровень): 024, 015, 002, 032 — модель
   зовёт их `pothole` (хотя есть класс Repair).
4. **Тени и бордюры/лотки**: 013 (маска = ТЕНЬ), 005/032 (бордюр).
5. **Мелочь по краям кадра**: боксы 42–62px в углах (обувь, дальние крапинки).

Замечание: поднять `det_conf` целиком не решает — реальные ямы бывают 0.29–0.85, а FP
0.26–0.63, диапазоны перекрываются. Нужны умные гейты, а не тупой порог.

## Наблюдённые пропуски (recall)
- Яма на **дальнем/косом кадре** не детектится ВООБЩЕ (0 откликов при conf 0.05):
  сцены 001/007/021/026 — найдено только с ближнего ракурса. Причина — мало
  пикселей + искажение ракурсом. Отсюда протокол «снимать вблизи».
- Нетипичные ямы (засыпана светлым бетоном, 6dyN) — 0 откликов у основного
  детектора, спасает второй проход (`--ensemble`).

## Приоритет 0 — Мерить (фундамент, иначе всё ниже — угадайка)
Собрать маленький **локальный held-out набор с разметкой** (даже 50–100 кадров).
Считать precision/recall и **долю FP по категориям** (авто-часть / заплатка / вне
дороги / тень / край). mAP на RDD2022-Czech бесполезен (train-contaminated).
Инфраструктура рядом: `scripts/prepare_local_finetune.py`, `scripts/val_rdd2022.py`.

**Инфраструктура ГОТОВА (цикл 14, протокол — `docs/EVAL.md`):**
`make_eval_set.py` (46 кадров ровно из сцен карты FP ниже, 20 held-out сцен;
`prepare_local_finetune.py` исключает их из обучения автоматически),
`build_eval_annotator.py` (офлайн-разметчик с предложениями движка),
`eval_detection.py` (precision/recall + FP-категории + CSV для mining).
**Осталась ручная разметка** 46 кадров в разметчике — после неё каждый пункт
ниже гейтится числами, а не глазами.

## Приоритет 1 — Убрать FP без обучения (дёшево, эффект сразу)
- **Вето по машинам/людям** [impact: высокий, effort: низкий]. Прогнать COCO-YOLO
  (уже есть в фолбэк-цепочке `DETECTOR_CANDIDATES`) и выкидывать `pothole`, чей бокс
  преимущественно внутри car/truck/bus/person/bicycle. Убивает класс FP «на машинах».
- **Гейт «на дороге»** [высокий, средний]. Отбрасывать детекции вне дорожной
  плоскости. Дёшево: верхняя часть кадра/над горизонтом + высокая насыщенность цвета
  (асфальт серый). Правильно: лёгкая сегментация проезжей части. Бьёт стены/баннеры/клумбы.
- **Разделение «яма vs заплатка/тень»** [средний-высокий, низкий]. Заплатка светлее
  фона и гладкая; тень — мягкий градиент без обода; яма темнее, шершавая, с
  кромкой/тенью. Критерий яркость+текстура(+кромка) понижает/переклеивает класс.
- **Мин. физ. размер + подавление у края кадра** [средний, тривиальный].

## Приоритет 2 — Ловить больше (recall)
- **Протокол съёмки вблизи** — уже в демо-отчёте; самый дешёвый рычаг.
- **Тайловый инференс (SAHI)** [высокий на дальних, средний]. Резать кадр 4096px на
  перекрывающиеся плитки, детектить по каждой, склеивать. Возвращает мелкие/дальние
  ямы, теряемые даунскейлом до 1024. Цена — больше compute.
- **imgsz 1280–1536** — более дешёвая частичная замена тайлингу.
- **Ансамбль/TTA** включать для нетипичных (бетон-засыпанные).

## Приоритет 3 — Сопоставление ямы в двух ракурсах
Сейчас `fusion.py` = «одна доминирующая яма в кадре», без сверки внешнего вида → уже
сматчил РАЗНЫЕ ямы (сцена 028). Нужно: сопоставление по признакам (ORB/LightGlue или
маленький эмбеддинг — проверка, что это то же место) + много-ямное назначение
(венгерский алгоритм по форме+положению), чтобы сцены с несколькими ямами матчились.

## Приоритет 4 — Долгосрочный фикс: дообучение + hard-negative mining
Инфраструктура готова (`scripts/finetune_rdd2022.py`), нужны локальные размеченные
РФ-кадры (двор, машины, муралы, бордюры). Ключевое: **скормить как негативы ровно те
FP из карты выше** (колёса, стены, заплатки, плакаты, клумбы, бордюры) → адресный
рост precision. Дальше — цикл активного обучения: модель → человек правит FP/пропуски
→ дообучение.

## Приоритет 5 — Сантиметры честно (разблокировать ГОСТ-вердикты)
На улице эталона нет. Дёшево и надёжно: **съёмка с маркером** (ArUco/AprilTag или
даже лист A4 у ямы) → корректные см. Альтернативы: люк отдельным классом детектора
(сейчас только хрупкий Hough/blob); фотограмметрия серии (даёт и глубину/объём — в
дорожной карте).

## Рост датасета и аугментация (вывод панели из 4 ракурсов, 2026-07-07)
Единогласный ответ на вопрос «растить датасет? искусственно аугментировать под наклоном?»:

**Синтетический наклон/перспективный варп для ДЕТЕКТОРА — почти театр, не вкладываться.**
- Наши пропуски на дальних/косых кадрах (001/007/021/026: 0 детекций даже при conf 0.05)
  — это проблема РАЗРЕШЕНИЯ (мало пикселей после даунскейла до 1024), а НЕ разнообразия
  ракурсов. Гомография-варп close-up кропа не уменьшает число пикселей → не воспроизводит
  отказ.
- Яма трёхмерна; её тень/ободовое затенение — ровно тот признак, которым пайплайн
  отличает яму от заплатки/тени (наша проблема precision №1). Плоский 2D-варп
  ПЕРЕРИСОВЫВАЕТ это затенение НЕВЕРНО → может активно ВРЕДИТЬ precision.
- Ultralytics `train()` уже включает scale/HSV/flip/mosaic по умолчанию; `perspective/
  degrees/shear` = 0 — включить их в `finetune_rdd2022.py` это бесплатные 5 минут, сделать,
  но считать мелким довеском, не фиксом recall.
- Где синтетика наклона ВАЛИДНА: тест МАТЕМАТИКИ масштаба (`demo_two_view.py` уже так
  делает) — расширить в регресс-свип по углам; НИКОГДА не как данные для обучения детектора.

**Что реально помогает (по возрастанию):**
1. **Held-out КАТЕГОРИЗИРОВАННЫЙ eval-набор — ПЕРВЫМ** (P0). ~50–150 кадров, боксы + тег
   FP-категории (авто/вне-дороги/заплатка/тень-бордюр/край), НИКОГДА не в обучении и не
   растить синтетикой. Без него всё ниже — угадайка. + харнесс precision/FP-по-категориям
   (сделано отдельным `scripts/eval_detection.py`, цикл 14 — НЕ расширять
   pair_quality_table). RDD2022-Czech mAP → понизить до «плумбинг-смоук».
2. **Hard-negative mining РЕАЛЬНЫХ FP-кропов** (колёса/заплатки/бордюры/муралы) — copy-paste
   на реальные дороги как негативы (реальные пиксели, не GAN; нужен базовый blend/масштаб).
   Бьёт precision №1. Растить РЕАЛЬНЫЕ кадры, целясь в 5 конфузоров: 300–400 таргетных
   кадров > 1000 случайных «красивых ям». ~10–15 чел-часов разметки.
3. **Дальний recall — только РЕАЛЬНЫЕ фото:** переснять 10–15 имеющихся ям с реально
   далёкого/косого ракурса (протокол `DATASET.md`) + imgsz-бамп/SAHI-тайлинг (P2).
4. **Self-training на неразмеченной груде — как ЧЕЛОВЕКО-ГЕЙТ actlearning, НЕ авто-accept.**
   Причина: conf ямы (0.29–0.85) перекрывает conf FP (0.26–0.63) → безопасного порога нет,
   авто-псевдолейблинг зацементирует FP-классы как «подтверждённые» с ростом уверенности
   (confirmation bias). Предложения модели → в очередь ревью (паттерн `build_measure_form.py`:
   кроп + accept/reject/reclass) → в обучение только принятое. Стоимость — ВРЕМЯ ревью, не GPU.
5. **Дисциплина дообучения:** ВСЕГДА от чекпоинта rezzzq, НИКОГДА от своего прошлого
   (иначе дрейф компаундится). Двухэтапно: A = негативы + 48 ям (precision); B = ревью-
   псевдолейблы + свежие косые/дальние кадры (recall). Гейт каждого этапа на eval-наборе.

**Пропустить:** CutMix/mixup (слабо для детекции), GAN/диффузия-синтез, 3D-рендер дорог —
без eval-набора не измерить пользу, sim2real-разрыв, а полдня реальной съёмки дворов/муралов
дешевле и вернее для столь локального домена.

**Честностная оговорка по SSL:** контракт проекта — модель может НИЧЕГО не сказать
(abstain). Петля, поощряющая уверенные предсказания везде, размывает это. Не штрафовать
«нет детекции» при обучении.

**Деплой:** ONNX/AGPL-снятие должно покрыть и `segment.py` (MobileSAM через
`ultralytics.models.sam`), не только детектор. Сначала профилировать латентность (SAM-энкодер
+ Depth-Anything дороже детектора), потом INT8. Любую ONNX-замену гейтить паритет-проверкой
(box/mask IoU) на eval-наборе.

### Рекомендованный порядок
(0) held-out КАТЕГОРИЗИРОВАННЫЙ eval-набор + харнесс precision/FP → (1) FP-гейты
(вето по машинам) + hard-negative mining → (2) тайлинг/imgsz + реальные косые кадры для
recall → (4) двухэтапное дообучение от rezzzq с человеко-гейт actlearning. Каждый шаг —
на наборе из (0). Синтетический наклон детектору НЕ растить (см. вывод панели выше).
