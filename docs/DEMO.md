## Ход презентации

### 1. Проблема (1 мин)

Учёт дорожных дефектов сегодня — ручной: инспектор фотографирует, на глаз
оценивает размеры, вручную заполняет акты. Цель платформы — по фото
автоматически получать: что за дефект, его контур, размеры, серьёзность по
ГОСТ Р 50597-2017 и кому направить предписание. Показываемый движок —
подсистема 1 из 5, фундамент платформы.

### 2. Ключевой тезис — честность измерений (2 мин)

> «Система никогда не выдаёт числа, которых физически не может знать».

Три уровня, которые стоит проговорить (таблица есть в шапке `PROJECT.md`):
- **Любое фото** → детекция, класс, контур, форма.
- **Фото с эталоном** → размеры в сантиметрах ±10–20%. Эталон — не только люк
  (ГОСТ 3634): поддержаны **разметка** (ГОСТ Р 51256) и **бордюр** (ГОСТ 6665)
  с кросс-проверкой. Рискованные пути (разметка/бордюр) по умолчанию ВЫКЛЮЧЕНЫ
  и дают только low-confidence: класс ширины разметки по одному штриху
  неоднозначен, а ложный масштаб хуже отсутствия эталона.
- **Два вида одной ямы** (`--pair`, «яма впереди» + «яма позади») → уточнение
  размеров обратно-дисперсионным слиянием и поправкой площади за наклон. Но
  глубину в см не выдаёт даже так — два косых кадра ≠ серия SfM.
- **Глубина в см по одному фото невозможна** — это физика монокулярного
  зрения, а не недоработка. Выдаётся только «мелкая/средняя/глубокая»;
  ГОСТ-глубина появится с серийной съёмкой (фотограмметрия, дорожная карта).

Это главное отличие от «магических» решений: оценщик доверяет каждому числу,
потому что движок отказывается угадывать.

### 3. Живой запуск (3 мин)

```powershell
$env:PYTHONPATH="src"
.\.venv\Scripts\python.exe -m road_defect.cli --input . --output outputs_live --depth --ensemble
```

Пока идёт (~1–2 мин на 6 фото на CPU), рассказать конвейер:
**YOLO-детектор** (открытые веса RDD2022, 5 классов) → **сегментация** —
класс-зависимая: ямы обводит нейросеть MobileSAM, трещины — классическая
экстракция тонких структур в полном разрешении (нейросеть на даунскейле 1024px
физически не видит трещину шириной 2px) → **дескрипторы формы** → **масштаб**
по люку, если он подтверждён → **вердикт ГОСТ** → JSON + размеченное фото.

### 4. Разбор результатов — demo_report.html (4 мин)

Открыть `outputs_demo\demo_report.html`. Идти сверху вниз:

- **Шапка**: сколько фото/дефектов, и витринный счётчик «0 ложных чисел».
- **Карточка JO7VcI…** (6 дефектов): богатое фото — яма, продольные и
  поперечные трещины; показать колонку «метод маски» (видно, чем получен
  каждый контур) и относительную глубину.
- **Карточка Q5pslz…** (1 яма, conf 0.89): образцовая маска MobileSAM —
  контур точно по краю выбоины.
- **Карточка 6dyN…** — история про инженерный цикл (самый сильный момент
  демо): основной детектор эту яму НЕ видел — она засыпана светлым бетоном и
  не похожа на тёмные ямы обучающего датасета; диагностика (`detect_sweep.py`)
  показала ноль откликов даже при пороге 0.01. Решение — второй
  pothole-проход (`--ensemble`): яма найдена с conf 0.81 и точной маской
  (видно в карточке). Плюс готова инфраструктура дообучения
  (`scripts/finetune_rdd2022.py`) для системного лечения на локальных данных.
  Показ слабости и её устранения вызывает больше доверия, чем сокрытие.
- **Бейдж ГОСТ** у каждого дефекта: «глубина не подтверждена — вердикт
  требует серийной съёмки» — снова принцип честности в действии.

### 5. JSON для интеграций (1 мин)

Открыть любой `outputs_demo\*.json`: стабильный контракт — классы, RLE-маски,
метрики с полосами ошибок, вердикты ГОСТ со сроками устранения. Подсистемы
2–5 (backend, карта, уведомления) подключаются к этому контракту без правок
движка.

### 6. Инженерная зрелость (1 мин, по желанию)

- 89 юнит-тестов + смок на реальных фото + автоматический валидатор инвариантов.
- Адверсариальное ревью кода независимыми ИИ-агентами (по два раунда в каждом
  цикле) — именно оно ловит ложные эталоны масштаба до того, как они попали бы
  в продукт (в цикле 4 так был пойман ложный масштаб разметки 2.5–5× по
  ориентации штриха — лечится тем, что разметка/бордюр выключены по умолчанию).
- Диагностические утилиты: `detect_sweep.py` (разбор пропусков),
  `scale_debug.py` (постадийный разбор эталона).

### 7. Дорожная карта (1 мин)

Фотограмметрия серии кадров (ГОСТ-глубина и объём) → ONNX-рантайм (чистые
лицензии) → backend + карта + автоотчёты ответственным → геолокация по EXIF.

## Ожидаемые вопросы и ответы

**— Почему нет глубины? Конкуренты показывают.**
По одному фото глубина не восстановима геометрически; кто показывает —
угадывает. Мы выдаём относительный приоритет сейчас и ГОСТ-глубину из серии
кадров в следующем цикле. Для предписаний по ГОСТ нужна доказуемая цифра.

**— Почему на демо-фото нет сантиметров?**
Масштаб берётся с эталона. На этих фото нет ни контрастного люка ГОСТ 3634, ни
чёткой разметки, которые детектор готов подтвердить, а неподтверждённый эталон
мы принципиально не используем (на одном из фото кандидатом в люк оказалась тень
под бордюром — фильтры её отбили; разметка на этих кадрах не детектируется). С
эталоном в кадре сантиметры появляются автоматически. Карточка пары внизу отчёта
показывает то же честное поведение режима `--pair`: ямы найдены в обоих видах, но
без эталона слияние см не фабрикует (`two_view_unmatched`).

**— Основной детектор пропускал яму на 6dyN — как это решено?**
Детектор обучен на RDD2022, где ямы тёмные; эта засыпана светлым бетоном —
ноль откликов даже при пороге 0.01. Решено вторым pothole-проходом
(`--ensemble`, видно в отчёте: conf 0.81), системно — дообучением на
локальных данных (инфраструктура готова, `scripts/finetune_rdd2022.py`).

**— Что нужно, чтобы запустить в моём городе?**
Фото с телефонов (любых), CPU-сервер. Для боевой точности — небольшой
локальный размеченный набор для дообучения (запланированный путь) и протокол
съёмки для серийного режима.

**— Лицензии чистые?**
Модели — Apache-2.0 (MobileSAM, Depth Anything Small). Обёртка ultralytics —
AGPL: до коммерческого релиза инференс переводится на ONNX (в плане), либо
покупается коммерческая лицензия.

## Контролируемое демо см-измерения и слияния (когда нет фото с эталоном)

На демо-фото нет эталона в кадре, поэтому см не выдаются. Чтобы показать F1/F2
«в числах» end-to-end, есть контролируемый прогон на синтетических кадрах с люком
известного размера (масштаб и математика — настоящие; застаблен только детектор
ямы, см. шапку скрипта):

```powershell
$env:PYTHONPATH="src"; .\.venv\Scripts\python.exe scripts\demo_two_view.py
# таблица в консоли + outputs_demo_synth\demo_report.html
```

Показывает: косой вид ЗАНИЖАЕТ площадь (≈703 см² вместо ≈949), а слияние двух
видов снимает ракурс и даёт ≈951 см² — точнее любого одиночного кадра; глубина
в см при этом остаётся `null` (два косых кадра ≠ серия SfM).
