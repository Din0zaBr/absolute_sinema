# Ридер глубины «рейка + рулетка» — план работ

Выбор заказчика 2026-07-15: «хочу глубину в сантиметрах» → путь 1 из
`DEPTH_RESULTS.md` §выводы-4а. Архивные фото см не дают (two-view 0/95;
фото-чтение косой рулетки отозвано — параллакс дальней кромки +5–10 см;
полевой факт: ямы набора 1–3 см). Путь 2 (маркер + серия, режим D ТЗ)
остаётся целевым для глубины без рулетки — не отменён, отложен.

## Протокол съёмки замера (новые выезды)

1. **Рейка/правило** (любой ровный жёсткий профиль длиннее ямы) кладётся
   ПОПЕРЁК ямы, опираясь на целое покрытие с обеих сторон.
2. **Рулетка вертикально**: крюк — на дно в самой глубокой точке, лента
   прислонена к рейке (касается её ребра), не провисает.
3. **Кадр** с 0.5–1 м: в кадре читаемы шкала ленты и точка пересечения
   рейка×лента; без сильного контрового света; лента ⟂ рейке.
4. Один кадр замера на яму; обзорный кадр ямы — как обычно (для детекции).

Физика: точка касания рейки и ленты лежит В ПЛОСКОСТИ ленты → параллакса
нет; глубина = чтение шкалы у нижней грани рейки минус 0 у крюка.

## Алгоритм v1 (`src/road_defect/ruler.py`, классический CV, без новых pip)

1. **Лента**: HSV-порог жёлтого (H≈15–45, высокие S,V) → крупнейшая
   вытянутая компонента (PCA: отношение осей ≥ 4) → minAreaRect →
   перспективная выпрямка в вертикальную полосу канонической ширины.
2. **Цена деления**: профиль тёмности по строкам выпрямленной полосы →
   периодические пики (см-риски); период px/см = медиана межпиковых
   расстояний; гейт: вариация периода ≤ 15%, пиков ≥ 8.
3. **Ноль**: физический конец ленты — крюк (не-жёлтый металлический
   терминус жёлтой полосы снизу). OCR не нужен.
4. **Рейка**: длинная прямая грань, пересекающая полосу ленты (Canny +
   HoughLinesP в окрестности ленты; берём НИЖНЮЮ грань силуэта рейки —
   сторону касания). Пересечение с осью ленты → строка чтения.
5. **Глубина** = (строка_касания − строка_крюка) / период. Полоса ошибки:
   остаток аппроксимации периода + σ локализации грани + 0.5 см допуск
   протокола (типично ±0.5–1 см).
6. **Гейты честного отказа** (available=false + reason, чисел нет):
   `no_tape` / `tape_not_elongated` / `ticks_aperiodic` / `hook_not_found` /
   `no_straightedge` / `crossing_too_oblique` / `blurred`. На архивных
   кадрах без рейки ридер обязан отказывать `no_straightedge` — это тест.

## Куда кладётся результат (честность)

- `metric.depth_cm` ОСТАЁТСЯ null (сертифицируемая глубина — только после
  полевой валидации §7 ТЗ; см. `TZ_MEASUREMENT.md`).
- Новый блок `metric.depth_cm_ruler` по образцу `depth_cm_estimate`:
  `{available, point_cm, low_cm, high_cm, method:"ruler_touchpoint_v1",
  confidence:"medium", certifiable:false, reason, note}`. Инструментальный
  замер, автоматически считанный; полоса обязательна.
- `scripts/validate_outputs.py` — инварианты блока (числа только при
  available, полоса накрывает точку, certifiable=false).
- Сначала standalone: `scripts/read_ruler_depth.py <фото|папка>` → JSON +
  оверлей (найденные лента/крюк/рейка/точка чтения). Интеграция в
  pipeline/webapp — ТОЛЬКО после полевой валидации.

## Валидация (гейтит включение в продукт)

1. Синтетика в тестах (`tests/test_ruler_reader.py`): рисуем cv2-сценку
   (лента с рисками+крюком, рейка, перспектива) с известной глубиной —
   восстановление ±0.5 см; каждый гейт срабатывает на своём вырожденном
   входе. Плюс прогон по 2–3 архивным ruler-кадрам → честный отказ.
2. Полевая: 5–10 ям по протоколу выше (снимает заказчик), сверка ридера с
   ручным чтением; цель MAE ≤ 1 см. До прохождения — фича живёт в scripts/.
