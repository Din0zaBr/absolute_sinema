## P1 — Честность / корректность измерений (чинить первым)

### 1. [CRITICAL/HIGH] Всегда-включённый путь люка не проверяет ВНЕШНИЙ ВИД → ложный масштаб
- **Где:** `scale.py:356-369` (Путь 1: `detect_manhole_circles` → `fit_manhole_ellipse`
  → `_ellipse_confirms_circle`). Гейты внешнего вида (тёмная сердцевина + опора
  периметра на Canny) есть ТОЛЬКО в Пути 2 `detect_manhole_ellipses:201-217`,
  который выключен по умолчанию (`allow_blob_reference=False`).
- **Суть:** Путь 1 принимает эталон на чисто ГЕОМЕТРИЧЕСКОМ согласии (Hough-круг ↔
  контурный эллипс: центр в пределах 0.35r, диаметр 1.4–2.9r) + гейт дорожной
  плоскости. Никакой проверки «это похоже на люк» (темнее кольца, резкая кромка).
  Единственное, что мешает круглой яме/заплатке стать люком, — `exclude_boxes`,
  т.е. что её УЖЕ поймал детектор. Docstring обещает «круглая яма/заплатка
  масштабом НЕ становится» (scale.py:20-22) — но реализация слабее обещания.
- **Сценарий отказа:** круглая яма ~50–70 см (диапазон люка 646 мм), которую YOLO
  ПРОПУСТИЛ (обычный режим отказа — слабый свет/дальний ракурс/просто miss). Hough
  ловит её как круг, эллипс садится на реальную границу (естественно, согласуется),
  сидит внизу кадра → принят как `manhole_gost3634_cover` 646 мм, возможно
  `confidence="high"`. ВСЕ сантиметры в кадре (и этой ямы, и соседних дефектов) и
  вердикт ГОСТ теперь построены на выдуманном масштабе. «Ложный масштаб хуже
  отсутствия масштаба» — прямое нарушение главного принципа.
- **Оговорка (честно):** срабатывает при конъюнкции (детектор пропустил И Hough
  сработал И эллипс согласовался И на плоскости И размер в полосе люка). Влияет
  только на Сценарий B (эталон в кадре); на уличном демо-наборе люков нет.
- **Фикс:** вынести гейты внешнего вида из Пути 2 в общий хелпер (контраст
  «сердцевина темнее кольца» ~line 207 + доля периметра на Canny ≥0.5 ~line 214-217)
  и применять их и в Пути 1. Приёмка эталона не должна держаться только на «два
  краевых детектора согласны друг с другом». Тест: круглая тёмная яма-заглушка без
  детекции → эталон НЕ выдан.

### 2. [MEDIUM-HIGH] Нет гигиены не-конечных чисел (NaN/Inf) → «дефект в норме» вместо ошибки
- **Где:** `severity.py:41-43` (нет NaN-гарда; сравнение с NaN всегда False →
  `non_conforming="no"`), `report.py:64` (`json.dumps(..., allow_nan=True)` по
  умолчанию → NaN/Infinity как невалидный JSON), `shape.apply_scale` (умножение без
  проверки — прокидывает NaN/Inf от вырожденного `mm_per_px`).
- **Суть/сценарий:** проверено исполнением: `severity.classify(nan, nan, nan)` →
  `non_conforming='no'` — опасный дефект отрапортован «в норме» без предупреждения.
  Если NaN/Inf когда-нибудь дойдёт (вырожденный масштаб: `diameter_px=0` →
  `mm_per_px=inf`), контракт JSON молча портится / вердикт врёт.
- **Фикс:** на входе `classify()` трактовать `math.isnan(x)` как `None`
  (indeterminate); в `apply_scale`/pipeline отбраковывать не-конечные с warning; в
  `save_report` — `allow_nan=False` (падать громко) ИЛИ рекурсивно заменять на
  `None`+warning. Дёшево, закрывает целый класс.

### 3. [MEDIUM] `--pair` принимает ОДИН файл как оба вида → ложное «независимое согласие»
- **Где:** `cli.py:102-118` (`_run_pair`) + `fusion.py:~250-306` (промоушен
  уверенности при `agreement=="agree"`).
- **Суть/сценарий:** `--pair yama.jpg yama.jpg` (опечатка/копия). Формы идентичны →
  `area_dis=0` → «agree»; при наличии tilt-эталона уверенность повышается на ступень
  с `confidence_promoted=true`. Отчёт заявляет независимо-кросс-проверенное
  двухракурсное измерение, хотя фото одно. См-гейт при этом честен (агент 2
  подтвердил: без совпадения → `two_view_unmatched`), но ярлык уверенности
  раздувается.
- **Фикс:** в `_run_pair`/`_discover_pairs` отклонять `a.resolve()==b.resolve()`
  (плюс, по желанию, сверка хеша содержимого) как явную ошибку.

## P2 — Корректность детекции

### 4. [MEDIUM; HIGH при `--ensemble`] Слияние ансамбля дублирует одну яму в две записи
- **Где:** `detect.py:56-71` (`merge_detections`, `iou_thr=0.5` захардкожен,
  вызывается без override на `detect.py:149`). NMS модели — `det_iou=0.45`.
- **Суть/сценарий:** порог слияния (0.5) ВЫШЕ NMS (0.45) и это единственный признак
  «тот же объект» между двумя разными моделями (rezzzq vs keremberke-seg). Их боксы
  на одной яме легко дают IoU 0.35–0.49 (seg-бокс vs обычный) → вторичная считается
  «новой» и добавляется → в JSON/overlay/ГОСТ **две записи на один физический
  дефект** (двойной учёт). `test_detect_merge.py` покрывает только IoU≈0.8.
- **Фикс:** вынести порог слияния в `InferenceConfig` (`ensemble_merge_iou≈0.3`),
  отдельно от NMS; добавить fallback по вложенности/центроиду для того же класса;
  тест на полосу умеренного перекрытия.

### 5. [MEDIUM] Второй проход игнорирует инъекцию `candidates`
- **Где:** `detect.py:127` — `_load_pothole_second_pass` берёт keremberke из
  глобального `config.DETECTOR_CANDIDATES`, а не из `self._candidates` (который
  конструктор принимает и `load()` использует корректно, `detect.py:93,99`).
- **Сценарий:** `Detector(cfg, candidates=[offline_only])` + `ensemble_pothole=True`
  всё равно лезет в глобальный реестр и пытается качать keremberke с HF —
  изоляция/детерминизм (CI, форс конкретной модели) молча ломается.
- **Фикс:** `next((c for c in self._candidates if c.name=="keremberke-...-seg"), None)`.

### 6. [MEDIUM] Ветка открытого люка (600 мм) недостижима + `type` захардкожен
- **Где:** `scale.py:322-331` (docstring обещает `known_mm=600` от вызывающего),
  `scale.py:418` (`type="manhole_gost3634_cover"` всегда), `scale.py:907` (един.
  вызывающий `resolve_scale` — 600 не передаёт никогда).
- **Сценарий:** открытый люк ~600 мм меряется как 646 → `mm_per_px` завышен на

- **Фикс:** `type`/`subtype` выводить из `known_mm`; либо подключить различение

## Алгоритм действий для Fable (как двигать проект вперёд)

**Порядок работы (по циклам проекта; коммиты `Цикл N: …` по-русски, не пушить без
явной просьбы, 129 тестов держать зелёными, в конце цикла — адверсариальное
пре-коммит ревью, оно ГЕЙТИТ коммит):**

1. **Сначала честность (P1).** Пункты 1–3 защищают главный принцип и дёшевы.
   Начни с №1 (гейт внешнего вида люка) — это единственная дыра в честном ядре,
   которую нашёл аудит; остальной масштаб/слияние проверены корректными.
2. **Затем корректность детекции (P2, №4–6).** №4 (дубли ансамбля) заметен при
   `--ensemble`; №5–6 — тихие, но реальные.
3. **Гигиена батчем (P3, №7–17).** Мелкие, но №8/№9/№14 задевают правила проекта
   (config-пороги, ГОСТ-категории, кириллица-I/O) — их стоит закрыть.
4. **Потом — рост качества** по `docs/IMPROVEMENTS.md` (борьба с FP, тайлинг для
   дальних, дообучение). ВАЖНО: перед любыми правками, меняющими метрики детекции,
   собери мини-набор для замера (P0 в IMPROVEMENTS) — иначе улучшения не измерить.

**Дисциплина на каждую находку:**
- Репро-тест первым (падающий) → фикс → `pytest -q` зелёный → адверсариальное ревью.
- Пороги/константы — только в `config.py` (не хардкодить; см. №8).
- Картинки — только через `imgio.py` (кириллица; см. №14).
- Ничего не выдумывать: если система не может знать число — не выдавать (принцип №1).

**Что уже проверено и ХОРОШО (не трогать без причины):** математика слияния
(обратная дисперсия, tilt-поправка `area/cos`, полосы ошибок), гейтинг
разметки/бордюра (только low-confidence, off by default, бордюр не может быть базой),
честное ядро глубины (`depth_cm` структурно всегда `None`), полноразрешающая
экстракция трещин, кириллица-safe чтение/запись в `imgio`, honest-mode инварианты
(`test_pipeline_honesty.py`). Аудит подтвердил: честный костяк держится, кроме
находки №1.
