## Сделано (2026-06-12, цикл 2: маски трещин + эталон-люк)

### Класс-зависимая сегментация: трещины больше не «заливаются»
- Линейные классы (D00/D10) сегментируются классикой в ПОЛНОМ разрешении внутри
  bbox: black-hat (тёмная трещина) → top-hat (трещина, забитая светлой пылью) →
  фильтры площади и **вытянутости** компонент (трещина вытянута, пятна тени и
  текстурный мусор округлы) → при неправдоподобном результате честный фолбэк
  в SAM/GrabCut. Площадные дефекты (яма/заплатка/сетка) — MobileSAM как раньше.
- В JSON у каждого дефекта новое поле `mask_method`
  (`detector_mask | crack_blackhat | crack_tophat | mobile_sam[_ultralytics] | grabcut`).
- Класс-зависимый порог отбраковки маски: линейные — 60 px (тонкая трещина
  3×60 px легальна), площадные — 200 px. Общий порог 200 терял уверенные
  детекции трещин целиком; при мелком результате крэк-экстрактора Segmenter
  сам уходит в SAM, чтобы детекция не пропадала из отчёта.
- Повторная визуальная верификация (4 агента): тёмные трещины **poor →
  acceptable** (узкая лента вдоль трещины, без заливки), маски ям остались good.
- ⚠ Известные ограничения (лечатся только специализированной crack-seg моделью,
  напр. дообучение на CrackSeg9k/SegmRDD): крупные пятна тени дают дугообразные
  (вытянутые) отклики по границе и просачиваются в маску; часть светлых трещин
  не проходит фильтры и честно падает в SAM-заливку (видно по mask_method).

### Эталон-люк: разбор завершён, найдены и исправлены 2 бага, путь для косых видов
- **Баг 1**: эвристика «крупнейший круг Hough = люк» на всех реальных фото
  выбирала гигантский фантом из текстуры (r≈370–472), и настоящий люк даже не
  проверялся. Теперь кандидаты перебираются в порядке силы отклика аккумулятора
  до первого подтверждённого (`detect_manhole_circles`).
- **Баг 2**: `fit_manhole_ellipse` брал ПЕРВЫЙ контур больше порога (порядок
  findContours произволен) — теперь ближайший к кандидату.
- **Фундаментальное**: HoughCircles не способен найти люк на косых смартфонных
  снимках (эллипс 2:1+). Добавлен второй путь — тёмный эллиптический блоб
  (`detect_manhole_ellipses`) с фильтрами: размер ≥8% короткой стороны, эллипс
  целиком в кадре, аспект ≥0.45 (наклон >63° бессмыслен и это профиль теней),
  заполненность контура 0.75–1.25, контраст с кольцом, опора ≥50% периметра на
  кромки Canny.
- ⚠ **Блоб-путь ВЫКЛЮЧЕН по умолчанию** (`--blob-ref` / `allow_blob_reference`):
  на реальном фото тень под бордюром прошла ВСЕ фильтры и стала ложным эталоном

  масштаб хуже отсутствия; включать после «золотой» валидации масштаба (§11).
- Конвейер переупорядочен: детекция → масштаб; bbox'ы дефектов исключаются из

  не выделяет — масштаб на них честно недоступен; системное решение — класс
