# Глубина по существующим фото (48 ям): что выжато и что честно нельзя

Дата: 2026-07-14, исправлено 2026-07-15 (полевой факт сборщика опроверг
фото-чтение рулеток — см. §«Ground truth»). Запрос: «выжать максимум глубины
из уже отснятых фото». Методология и уровни точности — `docs/TZ_MEASUREMENT.md`;
физика two-view — `docs/VEHICLE_CAPTURE.md` §3; прототип —
`src/road_defect/photogrammetry.py` v0.

## Данные

48 ям, на каждую: пара «перед/за» с рук (realme 13+ 5G, f_px≈3025 из EXIF,
высота/тангаж неизвестны) + 2 кадра «Эталоны» (рулетка ПОПЕРЁК ямы почти в
надир и рулетка ВЕРТИКАЛЬНО в яме).

**Полевой факт сборщика (2026-07-15): реальная глубина ям набора — 1–3 см
максимум.** Это опорная истина для всего ниже.

## Слои результата (от честного к экспериментальному)

1. **Бакеты относительной глубины** (продуктовый пайплайн, цикл 16,
   `--depth --pair`): 39/48 пар — доминирующая яма найдена, бакет везде
   «мелкая» (большинство — «ниже локального шума рельефа»); 9/48 — яма не
   найдена детектором. `depth_cm` = null везде. **Полевой факт 1–3 см
   подтверждает бакеты: ямы действительно мелкие.**
2. **См-оценка `depth_cm_estimate`** (цикл 16, требует эталона масштаба в
   кадре): 0/48 — ни в одной паре перед/за нет подтверждённого люка/эталона.
   Слой недоступен на этом наборе.
3. **Two-view plane+parallax (ЭКСПЕРИМЕНТ, режим C ТЗ)** — этот отчёт.
   `depth_certifiable=False` всегда; результаты исследовательские.

## Как считался слой 3 (`scripts/two_view_real_pairs.py`)

Прототип v0 + адаптация под ручные пары: f_px из EXIF; высота 1.60 м номинал;
тангаж — перебор 8×8 (10–40°); регистрация кольца усилена (AKAZE+SIFT общий
пул, ECC-доводка по полосовой яркости — встречный вечерний свет инвертирует
контраст микрорельефа, выживают только альбедо-фичи: швы, пятна, заплатки);
гейты честности прототипа сохранены (масштаб/анизотропия/перекрытие/покрытие
дна), порог инлаеров ослаблен 25→12 (компенсируется требованием плато по
сетке тангажей). Неоднозначность «две ямы в кадре» решается геометрически
(кандидаты топ-2, выбирает регистрация; двусмысленность → отказ), не re-ID.
Полоса ошибки: разброс по плату тангажей × высота ±10% × f ±2%. Плато из
1–2 конфигураций — отказ `insufficient_plateau` (одна конфигурация — точка,
а не воспроизводимое плато).

## Ground truth: фото-чтение рулеток ОТОЗВАНО (урок про параллакс)

Попытка: прочитать глубину каждой ямы с кадров вертикальной рулетки
(`datasets/gt_photos/NNN_ruler_2.jpg`, 6 независимых проходов). Результаты
чтения давали 3–17.5 см (медиана 7.5) — **сборщик опроверг: реально 1–3 см**.

Механизм систематической ошибки: глубина читалась по пересечению шкалы с
кромкой целого асфальта, чаще ДАЛЬНЕЙ (ближняя на низком косом кадре обычно
не видна или проецируется ниже основания ленты). Луч зрения к кромке ПОЗАДИ
ленты пересекает ленту на `H·(1 − D_ленты/D_кромки)` ВЫШЕ плоскости полотна:
при высоте съёмки ~0.5 м и кромке в 20–40 см за лентой это **+5–10 см ложной
глубины**. Заметки чтецов фиксировали симптом («читается только дальняя
кромка — завышает»; у ямы 023 вилка ближняя/дальняя 0–16 см), но масштаб
систематики был недооценён.

`datasets/gt_depth_readings.json` сохранён с флагом `WITHDRAWN_FOR_DEPTH`
(для глубины не использовать; `span_cm` по надирной поперечной ленте
параллаксом не затронут). Прежнее утверждение этого отчёта «38/47 ям глубже
порога ГОСТ 5 см» — **ОТОЗВАНО**.

Урок для протокола (человеку и алгоритму одинаково): вертикальную рулетку
можно читать только против **рейки/правила, лежащего поперёк ямы** — точка
касания рейки и ленты находится В ПЛОСКОСТИ ленты, параллакса нет (ровно
это требует §7 ТЗ), — либо строго сбоку вплотную к ленте. Кадры «рулетка в
яме, снятая наискось с метра» глубину не несут — ни для глаза, ни для CV.

## Two-view: итоги прогонов

| Прогон | Пар | Оценка | Отказы |
|---|---|---|---|
| fb (перед/за, дистанция 2.5–5 м) | 48 (28 уникальных сцен) | 1 → 0 после гейта плато | нет масок детектора 15; отказ всех конфигураций 32 |
| etalon (два близких кадра рулеток, малая база) | 47 | **0** | нет масок детектора 38; отказ всех конфигураций 9 |

Единственная прошедшая конфигурация (пара 012): dz = 1.4 см [1.25–1.57] —
**согласуется с полевым фактом 1–3 см**. Но плато из одной конфигурации из
64 — не воспроизводимый результат, а точка; гейт `PLATEAU_MIN_CONFIGS = 3`
оставлен, итог по архиву честно «0 подтверждаемых оценок из 95 прогонов»
(не «метод врёт» — «метод на этих данных не даёт доказуемых чисел»).

Доминирующие причины отказов, по слоям:
1. **Детектор не видит яму** — 15/48 fb-видов и 38/47 etalon-пар: надирные
   крупные планы и часть обзорных кадров вне домена обучения. Для протокола D
   это надо закрывать (дообучение на надир) — пункт в `IMPROVEMENTS.md`.
2. **Регистрация кольца разваливается** (`registration_failed:ransac`) —
   встречные виды с инверсией контраста микрорельефа (вечерний свет) и
   разноракурсные пары надир/косой: совпадающих альбедо-фич меньше 12.
3. Прошедшие регистрацию одиночные конфигурации гибнут на гейтах покрытия
   дна/масштаба/плато — и это правильно.

## Главные выводы (ред. 2026-07-15)

1. **Ямы набора мелкие (1–3 см, полевой факт) — и пайплайн об этом честно
   говорил**: бакет «мелкая»/«ниже шума рельефа» во всех 39 парах с
   детекцией. Продуктовый выход слоя 1 корректен как есть.
2. **Фото вертикальной рулетки, снятое наискось, глубину НЕ несёт** —
   параллакс дальней кромки завышает на +5–10 см. Чтение (человеком или
   алгоритмом) валидно только против рейки поперёк ямы в точке касания
   (§7 ТЗ) или строго сбоку. Первая попытка «GT с фото» отозвана целиком.
3. **Two-view на архиве: 0 подтверждаемых оценок из 95** — детекция вне
   домена на надирных кадрах, регистрация кольца рушится на встречном свете.
   Единственная одиночная конфигурация (012, 1.4 см) согласуется с полевым
   фактом, но одиночность ≠ доказательство. Точность выигрывается на съёмке.
4. **Сантиметры глубины из уже отснятых фото извлечь нельзя** — ни
   алгоритмом, ни глазом. Пути к честным см на новых съёмках: (а) рейка
   поперёк + вертикальная рулетка, фото точки касания — автоматизируемое
   чтение ±0.5–1 см без параллакса; (б) режим D ТЗ — маркерная доска +
   серия 6–10 кадров, ±1–2 см без рулетки в яме; (в) `depth_cm_estimate`
   при подтверждённом люке в кадре (уже в движке). Для актирования по ГОСТ —
   только (а)/(б) после полевой валидации §7.
